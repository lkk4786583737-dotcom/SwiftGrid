# 产品范围与迭代计划

[返回首页](../README.md) · [个人贡献与决策](PRODUCT_STORY_zh.md)

本文根据初代需求梳理、历史 PRD、探索方案与当前实现整理，更新于 2026-11-12。历史文档中的设想与目标值不作为已交付能力或实测指标。

## 用户任务与核心需求

面向需要周期性处理表格、已经有目标报表、但不擅长编程的业务人员。核心任务是：给定多工作表原始数据与已完成的目标样例，建立可验收的转换逻辑，并在下一期继续使用。

| 阶段 | 用户需要 | 当前产品响应 |
| --- | --- | --- |
| 准备输入 | 确认文件、工作表和目标是否正确 | 上传 / 粘贴、工作表预览 |
| 定义口径 | 减少手动描述复杂规则 | 源表＋目标样例驱动学习，必要时澄清 |
| 检查结果 | 判断结果与目标是否一致 | 全量执行、学习目标校验、结果预览、脚本查看 |
| 沉淀复用 | 下期避免重复建模 | 保存逻辑、结构匹配、新数据执行 |
| 交付使用 | 检查、展示并带走结果 | 报告、基础统计、图表与 Excel / 图片导出 |

初代需求集中在学习与复用；后续增加结果分析与可视化，让交付物可以直接检查和展示。输入预览与粘贴来自实际使用反馈。智能制表扩大了任务范围，目前尚未稳定。

## 按风险与依赖安排迭代

以下是下一阶段建议的验收方向，不是已达到的指标，也不承诺具体发布日期。

| 优先级 | 要解决的问题 | 拟采取的措施 | 验收方向 |
| --- | --- | --- | --- |
| P0：正确性 | 同结构数据也会改变业务含义 | 扩充独立测试集；覆盖空值、重复键、新类别、缺失季度、关联基数变化 | 同时检查完整结果、总量与业务约束；记录静默错误 |
| P0：结果契约 | 数据一致不等于 Excel 文件一致 | 明确字段、列序、类型、Sheet 名及模板支持范围 | 下载文件符合声明的契约；已知不支持项有明确反馈 |
| P0：执行边界 | 生成 Python 的风险高于普通文件转换 | 独立 Worker、资源限制、文件与网络权限；确认模型可见数据 | 限制越权与超额资源使用；有可复现的隔离验证 |
| P1：受控制表 | 只有源数据时缺乏验收目标 | 用户确认指标、分类映射和业务口径；评估受控计划与 Agent 运行框架 | 不明确时提问；计划可检查、可执行、可审计 |
| P2：数据知识基础 | 企业术语、字段关系和指标含义分散 | 探索 LLM Wiki 与业务本体，组织字段、指标、关系与口径版本 | 先验证企业意图理解与错误减少，再决定接入方式 |
| P2：完整分析流程 | 取数、制表和解释仍分散 | 连接自然语言取数、口径沉淀、复用与业务报告 | 每一步保留来源、确认点与可核对结果 |
| 服务化阶段 | 本机成功不等于可公开运营 | 认证、用户隔离、限流、预算、持久存储与运维 | 权限与费用可控后，再提供常驻公网体验 |

## 智能制表的方案选择

待评估的实现方式包括接入开源 Agent 运行框架、使用第三方 Agent 平台，以及自行实现受控运行框架并配套数据治理。比较重点是：业务口径能否显式确认、错误是否可追溯、最终值能否由确定性程序生成，以及部署成本与数据边界是否合适。

当前没有将其中某一条路线描述为已完成的架构升级。
