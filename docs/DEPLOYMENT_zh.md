# 运行与托管边界

[返回首页](../README.md) · [本地启动与 Docker](GETTING_STARTED_zh.md) · [后端架构](ARCHITECTURE_zh.md)

当前提供代码、可观看视频和可复查案例，尚未提供常驻公网交互服务。此前的临时隧道依赖本机运行，不作为长期作品体验入口。

## 当前支持的运行方式

| 方式 | 适合用途 | 说明 |
| --- | --- | --- |
| 前后端分别启动 | 本地开发 | Next.js 开发服务器与 FastAPI 分别运行 |
| 静态前端由 FastAPI 托管 | 本地完整体验 | 构建 `frontend/out` 后同源访问 8000 端口 |
| 单服务 Docker 镜像 | 受控环境中的部署与验证 | 镜像同时包含静态前端与 Python 后端；逻辑库需要持久卷 |

SwiftGrid 需要持续运行 Python、接收文件、通过 SSE 推送进度，并调用模型。只托管静态前端不能提供完整功能。

## 后续选择托管平台时的条件

容器平台或云服务器都需要支持：持续运行的进程、适当的 CPU / 内存、上传限制、SSE 长连接、HTTPS、服务端密钥与持久磁盘。平台的休眠策略、请求超时、费用和区域应在实际选型时根据官方信息确认；本项目当前没有绑定某个付费平台。

可复用仓库中的 Dockerfile。以下 Bash 示例将服务先绑定本机地址，由外层访问控制和反向代理负责受控访问：

```bash
docker build -t swiftgrid .
docker run -d --restart unless-stopped \
  --name swiftgrid \
  -p 127.0.0.1:8000:8000 \
  --env-file .env \
  -v swiftgrid-data:/app/data \
  swiftgrid
```

`.env` 由部署者在服务器创建，不提交仓库。至少配置可用的模型密钥、地址、模型名称，并设置 `SWIFTGRID_ALLOW_RUNTIME_CONFIG=false`，防止浏览器修改全进程配置。持久目录可能包含学习数据，应按业务数据管理。

## 共享服务尚需补齐的能力

- 登录认证、用户级数据与逻辑库隔离。
- 单次文件、并发、模型预算、资源使用上限与任务超时。
- 生成代码的独立执行环境；当前 AST 护栏不能替代强隔离。
- 数据保留与清理策略、备份、运行日志和 `/api/health` 监控。

这些是从本地单用户工具升级到共享服务的工作范围，尚未在当前版本全部完成。当前求职展示可通过视频和公开案例了解功能，并在受控本地环境运行。
